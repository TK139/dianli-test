# **电力知识图谱推理系统（Power Knowledge Graph Reasoning System）**

## **📌 项目简介**

本项目是一个基于大语言模型（LLM）与知识图谱（Knowledge Graph）相结合的**电力领域智能问答与推理系统**。系统通过构建电力设备、拓扑结构、运行参数等实体及其关系的知识图谱，结合 LLM 的语义理解与推理能力，实现电力场景下的智能问答、故障分析、设备关联查询等功能。

------

## **🧠 模型说明**

表格

| 项目     | 说明                                              |
| :------- | :------------------------------------------------ |
| 基座模型 | 基于开源大语言模型微调（具体见 `model/` 目录）    |
| 推理框架 | 本地推理 / API 调用（视配置而定）                 |
| 知识图谱 | Neo4j 图数据库存储电力设备拓扑与属性关系          |
| 检索方式 | 图查询（Cypher）+ 向量语义检索（可选）            |
| 推理模式 | 用户提问 → 意图识别 → 图谱子图检索 → LLM 生成回答 |

> ⚠️ 本 Demo 为演示用途，模型规模较小，适用于功能验证与二次开发参考。

### 🗺️ 5.1 交互拓扑 —— 配电网实时拓扑可视化

**作用**：以力导向图形式渲染当前配电网的实时运行拓扑，直观展示设备实例之间的
电气连接、供电、归属等关系，是日常巡视和故障定位的"总览地图"。

**页面内容**：
- **彩色节点** = 设备实例：橙色 = 馈线/线路段（LP-003、LP-006）、绿色 = 变压器（T-003）、
  蓝色 = 开关（S-003）、红色 = 变电站（SS-01）、深色 = 母线（BUS-01/03）等；
- **灰色节点** = 本体类与关系节点（PowerEquipment、Outage、Event、Customer 等）；
- **带标签的边** = 关系类型：`CONNECTED_TO`（电气连接）、`SUPPLIES`（供电）、
  `BELONGS_TO`（归属）、`HAS_DOMAIN` / `HAS_RANGE`（本体约束）等。

**怎么用**：
1. 点击顶部「交互拓扑」页签，系统自动加载实时拓扑；
2. 拖拽、缩放画布浏览全网结构；
3. 观察节点颜色与连线，确认设备接入关系和当前网络形态；
4. 配合左侧"79 节点 / 65 边"统计，核对图谱数据是否完整导入。

**典型场景**：日常巡视、数据导入后的完整性核验、故障时的影响范围目视定位。

### 🧬 5.2 本体模型 —— 本体 Schema 结构查看

**作用**：展示知识图谱的"元层"设计，即 PowerOntology 的类层级、属性定义与语义关系，
相当于整个系统的**建模蓝图 / 数据字典**。

**页面内容**：
- **中部 Schema 图**：蓝色矩形为类（Customer 用户、PowerEquipment 电力设备、
  Outage 停电事件、Fault 故障、TieSwitch 联络开关、MaintenanceWorkOrder 检修工单等），
  橙色箭头为语义关系（供电给、影响用户、影响设备、发生故障、导致停电、经…恢复供电、针对设备、具有量测等）；
- **右侧类列表**：全部 23 个类（PowerEquipment、Substation 变电站、Feeder 馈线、
  LineSegment 线路段、Switch 开关、CircuitBreaker 断路器……）；
- **右侧属性列表**：全部 17 个属性（suppliesPowerTo 供电给、poweredBy 由…供电、
  upstreamOf 位于上游、downstreamOf 位于下游……）。

**怎么用**：
1. 点击「本体模型」页签；
2. 浏览 Schema 图，理解领域建模逻辑（如：设备 →发生故障→ 故障 →导致停电→ 停电事件 →影响用户→ 用户）；
3. 在右侧表格中查阅每个类 / 属性的 ID 与中文名称；
4. 二次开发、扩充数据或编写自定义 Cypher 查询前，先在此页确认类名与属性名。

**典型场景**：理解系统设计、开发调试、对外讲解本体建模思路。

### 🧠 5.3 公理推理 —— 规则引擎手动验证

**作用**：对**单条预定义公理**（推理规则）进行手动执行，验证系统在实时拓扑上的
逻辑推断能力，如故障传播、过载检测、负荷转供等。

**页面内容**：
- 公理下拉框（共 10 条公理），选中后显示该公理的**自然语言描述**与**逻辑表达式**，例如：
  > AX-001 故障传播规则：开关分闸时，其下游所有设备失电
  > `switchState(?s,'open') ∧ upstreamOf(?s,?d) → outageStatus(?d,true)`
- 参数输入框（如：开关ID）；
- 「执行推理」按钮与结果表（device / type / hops）。

**怎么用**：
1. 点击「公理推理」页签；
2. 在「选择公理」下拉框中选择要验证的规则（如 AX-001 故障传播规则）；
3. 在输入框填写参数（如开关ID：`S-001`）；
4. 点击「执行推理」；
5. 查看结果表：受影响的设备（F-001 馈线、T-001 变压器）、设备类型、拓扑跳数（hops）。

**典型场景**：调度操作前的停电范围预演、单条推理规则的演示与验收。

### ⚠️ 5.4 告警分析 —— 一键电网健康扫描

**作用**：基于公理规则集**自动扫描**当前实时拓扑，批量检测故障、停电、过载等
异常状态，输出告警结论，相当于"全自动版"的公理推理。

**怎么用**：
1. 点击「告警分析」页签；
2. 点击「🔍 扫描当前电网状态」按钮；
3. 查看扫描结果：
   - 正常时显示绿色提示：✅「当前电网运行正常，未发现告警」；
   - 异常时逐条列出告警（告警类型、关联设备、触发公理），可回到「交互拓扑」页定位设备。

**典型场景**：例行巡检、故障注入/开关操作后的全网状态复核。

### 🤖 5.5 AI推理 —— 大模型 × 本体融合推理

**作用**：系统的核心亮点。将**大语言模型**与本体知识、实时拓扑、推理引擎三者融合：
LLM 不凭空作答，而是以图谱与推理引擎返回的真实数据为依据，生成结构化分析报告。
支持**示例验证**与**自然语言自由提问**两种方式。

**页面内容**：
- **示例验证题目**（每题对应一条公理）：
  - Q1 · 故障传播分析（AX-001）
  - Q2 · 过载检测（AX-002）
  - Q3 · 负荷转供（AX-003）
  - Q4 · 用户停电影响（AX-005）
  - Q5 · N-1 安全校验（AX-008）
- **对话记录区**：展示用户提问与 AI 的完整分析过程。

**怎么用**：
1. 点击「AI推理」页签；
2. **示例验证**：展开任一题目（如 Q1），阅读题干后点击「🚀 开始推理」；
   **自由提问**：直接在输入框用自己的话提问，如"S-001 断开后哪些用户会停电？"；
3. 在「对话记录」中查看 AI 报告，报告通常包含：
   - 设备定位与拓扑关系确认（基于本体，如 S-001 类型为 SectionalizingSwitch 分段开关、当前状态合闸）；
   - 推理引擎返回的影响设备与跳数（F-001 hops=1、T-001 hops=1）；
   - 结合公理（AX-001 故障传播、AX-004 隔离规则等）的传播分析；
   - 影响范围结论与隔离 / 恢复供电建议。

**典型场景**：调度员智能问答、故障处置辅助决策、"大模型 + 知识图谱"技术路线的对外演示。
